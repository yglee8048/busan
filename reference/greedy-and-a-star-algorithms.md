# 그리디 알고리즘과 A* 알고리즘

## 한 줄 요약

- **그리디 알고리즘**은 매 순간 가장 좋아 보이는 선택을 하고, 그 선택을 되돌리지 않으면서 해를 만든다.
- **A\* 알고리즘**은 출발점부터 지금까지 든 실제 비용과 목적지까지 남은 예상 비용을 함께 고려해 최소 비용 경로를 찾는다.

두 알고리즘 모두 현재 상태에서 유망한 선택을 우선한다는 공통점이 있다. 그러나 일반적인 그리디 알고리즘은 문제의 구조가 특별한 조건을 만족할 때만 최적해를 보장하는 반면, A*는 적절한 휴리스틱을 사용하면 최단 경로를 보장하도록 설계된 탐색 알고리즘이다.

---

## 1. 그리디 알고리즘

그리디 알고리즘은 전체 문제를 여러 번의 선택으로 나누고, 각 단계에서 **당장 가장 이득이 크거나 비용이 작은 선택**을 한다. 이미 내린 선택은 보통 다시 검토하지 않는다.

```text
현재 상태
   ↓
지금 선택할 수 있는 후보를 평가
   ↓
가장 좋아 보이는 후보 하나를 선택
   ↓
문제가 끝날 때까지 반복
```

이 방식은 미래의 모든 경우를 탐색하지 않기 때문에 구현이 단순하고 빠른 경우가 많다. 하지만 현재의 최선이 전체의 최선으로 이어진다는 보장은 문제마다 따로 증명해야 한다.

### 1.1 핵심 성질

그리디 알고리즘으로 최적해를 구하려면 일반적으로 다음 두 성질이 필요하다.

#### 그리디 선택 속성

현재 단계의 최선의 선택을 포함하는 최적해가 존재해야 한다. 즉, 지금 가장 좋아 보이는 선택을 해도 전체 최적해에 도달할 가능성을 잃지 않아야 한다.

#### 최적 부분 구조

문제의 최적해가 부분 문제의 최적해로 구성되어야 한다. 한 번 선택하고 남은 문제 역시 같은 방식으로 최적으로 풀 수 있어야 한다.

이 두 성질은 그리디 알고리즘을 적용하기 전에 검토해야 할 조건이지, 그리디 방식으로 구현했다는 이유만으로 자동으로 성립하는 조건은 아니다.

### 1.2 대표 예시: 활동 선택 문제

한 회의실에서 서로 시간이 겹치지 않도록 최대한 많은 회의를 열려고 한다. 이 문제에서는 **종료 시간이 가장 빠른 회의를 먼저 선택**하면 최적해를 얻을 수 있다.

| 회의 | 시작 | 종료 |
|---|---:|---:|
| A | 1 | 4 |
| B | 3 | 5 |
| C | 0 | 6 |
| D | 5 | 7 |
| E | 8 | 9 |

종료 시간순으로 확인하면 다음과 같이 선택한다.

```text
A(1~4) 선택
→ A와 겹치는 B, C 제외
→ D(5~7) 선택
→ E(8~9) 선택

결과: A, D, E
```

가장 빨리 끝나는 회의를 선택하면 이후 회의를 배치할 수 있는 시간을 가장 많이 남긴다. 어떤 최적해의 첫 회의를 가장 빨리 끝나는 회의로 교체해도 뒤의 일정은 손해를 보지 않는다는 교환 논증으로 최적성을 증명할 수 있다.

### 1.3 기본 형태

```text
greedy(candidates):
    answer = []

    while candidates가 비어 있지 않다:
        candidate = 현재 기준에서 가장 좋은 후보

        if candidate를 추가해도 제약 조건을 만족한다:
            answer에 candidate를 추가한다

        candidates에서 candidate를 제거한다

    return answer
```

실제 시간 복잡도는 후보를 평가하고 선택하는 방법에 따라 달라진다. 후보를 한 번 정렬한 뒤 순회하는 유형은 보통 `O(n log n)`이고, 우선순위 큐를 사용하면 삽입과 삭제마다 `O(log n)`이 든다.

### 1.4 그리디가 실패하는 예: 동전 교환

동전 단위가 `1, 3, 4`이고 합계 `6`을 만들려는 경우, 매번 가장 큰 동전을 고르면 다음 결과를 얻는다.

```text
그리디 선택: 4 + 1 + 1 = 동전 3개
최적해:      3 + 3     = 동전 2개
```

한국의 일반적인 동전 체계처럼 큰 단위부터 고르는 방법이 우연히 최적인 체계도 있지만, 임의의 동전 단위에서는 항상 성립하지 않는다. 이 경우에는 동적 계획법 등 다른 방법이 필요하다.

### 1.5 대표적인 활용 사례

- 활동 선택 문제
- 분할 가능한 배낭 문제
- 크루스칼·프림 최소 신장 트리 알고리즘
- 다익스트라 최단 경로 알고리즘(간선 비용이 음수가 아닐 때)
- 허프만 코딩

각 사례는 서로 다른 기준으로 지역 최선의 선택을 한다. 따라서 “그리디를 사용한다”는 사실보다 **어떤 선택 기준이 왜 최적해를 보장하는지**가 더 중요하다.

## 2. 그리디 최우선 탐색

A*와 비교할 때 말하는 그리디는 보통 일반적인 설계 기법 전체가 아니라 **그리디 최우선 탐색(Greedy Best-First Search)**을 뜻한다.

그리디 최우선 탐색은 목적지에 가장 가까워 보이는 노드를 먼저 탐색한다. 노드 `n`에서 목적지까지 남은 예상 비용을 `h(n)`이라고 하면 우선순위는 다음과 같다.

```text
평가값 = h(n)
```

`h(n)`이 작은 노드일수록 먼저 탐색한다. 출발점부터 현재 노드까지 실제로 얼마나 큰 비용을 썼는지는 고려하지 않는다.

장애물이 없는 지도에서는 목적지를 향해 빠르게 나아갈 수 있지만, 막다른 길이나 큰 우회 비용이 있는 지도에서는 잘못된 방향을 오래 탐색하거나 더 비싼 경로를 반환할 수 있다.

## 3. A* 알고리즘

A*는 가중 그래프에서 출발 노드부터 목표 노드까지의 최소 비용 경로를 찾는 최우선 탐색 알고리즘이다. 각 노드의 우선순위를 다음 함수로 계산한다.

```text
f(n) = g(n) + h(n)
```

| 값 | 의미 |
|---|---|
| `g(n)` | 출발점에서 현재 노드 `n`까지 실제로 든 비용 |
| `h(n)` | 현재 노드 `n`에서 목표점까지 남은 비용의 추정값 |
| `f(n)` | 현재 경로를 거쳐 목표에 도달할 것으로 예상되는 총비용 |

A*는 목적지만 보고 달려가는 대신, 이미 지불한 비용과 앞으로 지불할 것으로 예상되는 비용 사이의 균형을 잡는다.

### 3.1 동작 과정

A*는 앞으로 탐색할 노드를 담는 `open` 우선순위 큐와 이미 처리한 상태를 관리하는 자료구조를 사용한다.

```text
1. 출발 노드의 g를 0으로 설정하고 open에 넣는다.
2. open에서 f가 가장 작은 노드를 꺼낸다.
3. 꺼낸 노드가 목표라면 부모 포인터를 따라 경로를 복원한다.
4. 이웃 노드까지 가는 새로운 g를 계산한다.
5. 기존에 알려진 경로보다 싸다면 g와 부모를 갱신하고 open에 넣는다.
6. open이 빌 때까지 2~5를 반복한다.
```

중요한 점은 목표 노드를 **처음 발견했을 때**가 아니라, 일반적으로 목표 노드가 우선순위 큐에서 **가장 작은 값으로 꺼내졌을 때** 탐색을 종료한다는 것이다.

### 3.2 의사 코드

다음 의사 코드는 같은 노드의 더 나은 경로가 나중에 발견될 수 있도록 허용한다.

```text
a_star(start, goal):
    open = f값이 작은 노드를 먼저 꺼내는 우선순위 큐
    open.push(start, priority = h(start))

    g[start] = 0
    parent[start] = 없음

    while open이 비어 있지 않다:
        current = open.pop()

        if current가 goal이다:
            return parent를 따라 복원한 경로

        for each next in current의 이웃:
            new_g = g[current] + cost(current, next)

            if next를 처음 방문했거나 new_g < g[next]:
                g[next] = new_g
                parent[next] = current
                f = new_g + h(next)
                open.push(next, priority = f)

    return 경로 없음
```

실제 구현에서는 우선순위 큐에 같은 노드의 오래된 항목이 남을 수 있다. 꺼낸 항목의 비용이 현재 저장된 최선의 비용보다 크면 건너뛰는 방식으로 처리할 수 있다.

### 3.3 휴리스틱 함수

휴리스틱 `h(n)`은 A*의 탐색 성능과 최적성에 큰 영향을 준다.

#### 허용 가능성

휴리스틱이 실제 남은 최소 비용을 절대로 초과 추정하지 않으면 **허용 가능하다(admissible)**고 한다.

```text
0 ≤ h(n) ≤ 실제로 남은 최소 비용
```

허용 가능한 휴리스틱을 사용하는 A* 트리 탐색은 최적 경로를 보장한다.

#### 일관성

모든 간선 `(n, n')`에 대해 다음 조건을 만족하면 **일관적이다(consistent)**라고 한다.

```text
h(n) ≤ cost(n, n') + h(n')
```

일관적인 휴리스틱에서는 경로를 따라 `f` 값이 감소하지 않는다. 그래프 탐색에서 노드를 한 번 확정한 뒤 다시 열지 않고도 최적성을 보장하기 쉬워진다. 휴리스틱이 허용 가능하지만 일관적이지 않다면 더 싼 경로가 발견된 노드를 다시 탐색해야 할 수 있다.

#### 격자 지도에서 자주 쓰는 휴리스틱

| 이동 방식 | 휴리스틱 | 계산식 |
|---|---|---|
| 상하좌우 이동, 동일 비용 | 맨해튼 거리 | `|x1-x2| + |y1-y2|` |
| 모든 방향의 직선 이동 | 유클리드 거리 | `sqrt(dx² + dy²)` |
| 대각선 포함 8방향, 동일 비용 | 체비쇼프 거리 | `max(|dx|, |dy|)` |

이동 규칙과 비용에 맞지 않는 휴리스틱은 실제 비용을 과대평가해 최적 경로 보장을 깨뜨릴 수 있다. 예를 들어 대각선 이동 비용이 상하좌우 이동과 같은데 맨해튼 거리를 쓰면 남은 비용을 과대평가할 수 있다.

### 3.4 휴리스틱에 따른 변화

```text
h(n) = 0
→ f(n) = g(n)
→ A*는 다익스트라 알고리즘처럼 동작한다.

h(n)이 실제 남은 비용에 가까운 허용 가능한 값
→ 불필요한 노드를 적게 탐색하면서 최적 경로를 찾는다.

g(n)을 무시하고 h(n)만 사용
→ 그리디 최우선 탐색이 된다.
```

허용 가능한 두 휴리스틱 `h1`, `h2`가 있고 모든 노드에서 `h1(n) ≤ h2(n)`이라면, 일반적으로 실제 비용에 더 가까운 `h2`가 더 적은 노드를 탐색한다. 다만 휴리스틱 계산 자체가 지나치게 비싸면 전체 실행 시간은 오히려 늘 수 있다.

### 3.5 시간과 공간 복잡도

A*의 비용은 그래프 구조와 휴리스틱의 품질에 크게 좌우된다.

- 우선순위 큐의 삽입과 삭제는 보통 `O(log V)`이다.
- 휴리스틱이 거의 정보를 주지 못하면 다익스트라처럼 많은 노드와 간선을 탐색할 수 있다.
- 일반적인 상태 공간 탐색에서는 최악의 경우 깊이에 대해 지수적으로 많은 노드를 탐색할 수 있다.
- 방문 후보와 경로 정보를 메모리에 보관하므로, 실무에서는 실행 시간보다 메모리가 먼저 한계에 도달하기도 한다.

그래프 전체가 명시되어 있고 각 노드를 제한된 횟수만 처리하는 전형적인 구현은 우선순위 큐 비용을 포함해 대략 `O((V + E) log V)`로 표현할 수 있다. 그러나 이는 상태 공간의 크기 자체가 작다는 뜻은 아니며, 재탐색 여부와 구현 방식에 따라 달라진다.

## 4. 그리디 최우선 탐색과 A* 비교

| 항목 | 그리디 최우선 탐색 | A* |
|---|---|---|
| 평가 함수 | `h(n)` | `g(n) + h(n)` |
| 고려하는 정보 | 목표까지의 예상 비용 | 지금까지의 실제 비용 + 남은 예상 비용 |
| 장점 | 목표 방향으로 빠르게 진행할 수 있음 | 조건을 만족하면 최소 비용 경로 보장 |
| 단점 | 비싼 우회로나 막다른 길에 취약 | 더 많은 메모리와 계산이 필요할 수 있음 |
| 완전성 | 구현과 그래프 조건에 따라 다름 | 양의 최소 간선 비용과 유한한 분기 등 적절한 조건에서 완전 |
| 최적성 | 일반적으로 보장하지 않음 | 허용 가능·일관적 휴리스틱과 올바른 구현에서 보장 |

간단히 표현하면 다음과 같다.

```text
그리디 최우선 탐색: “목적지에 지금 가장 가까워 보이는가?”
A*:                   “여기까지 온 비용까지 포함해 가장 유리한가?”
```

## 5. 어떤 알고리즘을 선택할 것인가

### 그리디 알고리즘이 적합한 경우

- 문제에 그리디 선택 속성과 최적 부분 구조가 있음을 증명할 수 있다.
- 최적해보다 빠르고 단순한 근사해가 더 중요하다.
- 입력이 매우 커서 모든 조합을 탐색하기 어렵다.
- 각 선택을 되돌리지 않는 방식이 문제의 제약과 잘 맞는다.

### A*가 적합한 경우

- 지도, 게임, 로봇 이동처럼 출발점과 목적지 사이의 최소 비용 경로가 필요하다.
- 목표까지 남은 비용을 추정할 수 있는 유용한 휴리스틱이 있다.
- 최단 경로의 정확성과 탐색 속도를 함께 확보해야 한다.
- 탐색 중 생성되는 노드를 저장할 메모리를 감당할 수 있다.

### 다른 방법을 고려해야 하는 경우

- 가중치가 모두 같고 휴리스틱이 없다면 너비 우선 탐색이 단순하다.
- 간선 비용이 음수가 아니고 적절한 휴리스틱이 없다면 다익스트라가 적합하다.
- 음수 간선이 있다면 일반적인 A*나 다익스트라를 사용하면 안 된다.
- 메모리가 부족하다면 IDA*처럼 메모리 사용량을 줄인 변형을 검토할 수 있다.
- 완전한 최적성보다 속도가 중요하다면 가중 A*나 그리디 최우선 탐색을 고려할 수 있다.

---

## 6. 적용 전 확인 목록

### 그리디 알고리즘

1. 매 단계에서 무엇을 기준으로 가장 좋은 후보를 선택하는가?
2. 그 선택을 되돌리지 않아도 되는 이유를 설명할 수 있는가?
3. 교환 논증이나 귀류법 등으로 최적성을 증명할 수 있는가?
4. 작은 반례를 만들어도 알고리즘이 최적해를 반환하는가?

### A* 알고리즘

1. 모든 간선 비용이 음수가 아닌가?
2. `g(n)`이 더 작아졌을 때 노드와 부모 정보를 갱신하는가?
3. 휴리스틱이 실제 비용을 과대평가하지 않는가?
4. 일관적이지 않은 휴리스틱이라면 노드를 다시 열 수 있는가?
5. 목표를 발견한 순간이 아니라 올바른 시점에 탐색을 종료하는가?
6. 경로가 없을 때 `open`이 비는 경우를 처리하는가?

## 핵심 정리

그리디 알고리즘은 **현재의 최선이 전체의 최선으로 이어지는 문제 구조**를 이용한다. 빠르고 단순하지만, 선택 기준의 정당성을 증명하지 못하면 최적해를 놓칠 수 있다.

A*는 경로 탐색에서 `g(n)`과 `h(n)`을 결합해 **지금까지의 실제 비용과 앞으로의 예상 비용을 동시에 최소화**한다. 좋은 휴리스틱은 정답을 바꾸지 않으면서 탐색 범위를 줄이며, 최적 경로 보장을 위해서는 휴리스틱의 허용 가능성·일관성과 올바른 갱신 로직이 중요하다.
